## What JEMS is
JEMS helps final-year students get hired by MSMEs. A student signs in, rates their skills, connects GitHub and LeetCode, takes a skill assessment, and sees a skill report. The report is compared with what MSME roles require to show their gaps. Then they follow a roadmap, with lessons and a mini-assessment for each gap, to close those gaps.

## Rules
- Use only the existing theme tokens through useColors(), fonts and radius. Never hard-code hex values. Light and dark must both work.
- Reuse existing ui components. If something is missing (segmented control, score ring, timeline item, radio option card, code block), add it to src/components/ as a small reusable component in the same style.
- Icons come from lucide-react-native, matching the PDF.
- Routes go in src/app/ using expo-router. Put the JEMS routes in their own folder (for example src/app/student/jems/) so they don't touch the existing exam screens. Keep non-route code outside src/app/.
- Data: there is no JEMS backend yet. Create src/lib/jems.ts with typed models and a mock data layer that uses the sample data from the PDF. Keep every screen reading data through that layer so we can swap in real API calls later without touching the UI. Do not modify existing API code.
- Quality: touch targets at least 44px, accessibilityLabel on icon-only buttons, safe-area handling, scrollable screens, keyboard-aware forms, pull-to-refresh where the existing screens have it.
- State: keep the onboarding answers (profile, skills, links) in a small context or store so steps 2-4 can go back and forward without losing input.
- Install packages only with `npx expo install`, and avoid adding new dependencies unless truly needed.
